PART 01

产品经理的定义、特质与分类

定义

产品经理 = 企业中专门负责「产品管理」的岗位。

产品经理在互联网公司中，是一个灵魂的角色。

必备的四种软实力

课上开宗明义给出的四个特质，顺序不是随便排的——从"你怎么让事情动起来"，一路推到"事情出问题谁扛"。

MVP：从"更快的马"说起

MVP = 最小可执行版本（Minimum Viable Product）。课上用马车案例引出——就是福特那句名言。

三种分类方式

问"你是做什么产品的"，其实是在问三个维度上的坐标。

端的差别里最关键的一条：交互类型

◆ 高频考点

移动端是线性交互，PC / Web 端是非线性交互。这一条在第 08 节讲「沉浸式导航很难做，因为它违反线性交互原则」时会再次用到。

一条职业建议

◆ 课上原话

从第一天开始就考虑：毕业之后要做什么类型的产品经理？

建议先考虑「行业」，再考虑其他。

因为行业知识的积累是最慢的，也最难跨。B/C 端、前后台都可以换，行业换起来代价最大。

另外：平时要多体验产品，尤其是国民级产品、现象级产品、明星产品。

产品经理的六类工作

PART 02

项目组成员及如何配合

这一节的价值全在「怎么打交道」上。角色本身不难记，难的是每种角色的相处方式。

UI 设计师

⚠ 红线

不要称 UI 为「美工」。

  • 产品经理不需要具备专业的设计能力，但需要有基本的审美
  • 怎么提升审美：① 多看奢侈品网站；② 多看设计类网站和产品（站酷、花瓣）

交互设计师

  • 多数企业中，都是由产品经理兼任交互设计师 —— 所以第 08 节的交互说明是必修
  • 怎么沟通：① 传达清楚需求；② 说不明白就找个例子给他看

开发工程师：新人最容易混的一组概念

角色负责
前端页面和交互实现
后端数据和逻辑关系
⚠ 必须分清

「前台 / 后台」和「前端 / 后端」是两回事。前台后台按页面区分（给谁用的），前端后端按开发语言区分。

无论前台还是后台，都是由前端 + 后端共同开发的。

怎么跟开发沟通

  1. 要多沟通
  2. 放低姿态，不懂就多请教
  3. 平时多充充电 —— 懂点技术才不会提出离谱需求

测试工程师

  • 测试主要就是找 bug
  • 建议：帮着做测试，积极主动

运营经理：四种运营

📝
内容运营
内容的生产与分发
👥
用户运营
拉新、留存、活跃
🎉
活动运营
策划执行活动
🔗
渠道运营
投放与合作

怎么沟通：积极沟通，互通有无。

PART 03

项目的工作流程

五个阶段，每个阶段都有明确的产出物。记流程的关键是记产出物 —— 阶段是抽象的，产出物是实的。

阶段产出物要点
启动BRD、MRD⚠ 不一定由产品经理完成
规划需求池、竞品分析、PRD、原型、流程图、结构图产品经理产出最密集的阶段
执行需求评审「产品经理需要有一颗强大的内心」（第 10 节还会再说一遍）
跟进—盯进度，处理开发过程中的问题
上线验收验收很重要；⚠ 上线之后要发上线通知邮件
PART 04

3D 文档：BRD / MRD / PRD

三份文档最核心的区别不是内容，是读者。记住"给谁看"，其他都能推出来。

BRD 的要点：最大的风险是政策

⚠ 课上强调

互联网公司做项目时，最大的风险来源是「政策」。

课上推荐的应对办法：装一个 人民日报 App，跟政策风向。

这一条对应第 02 节 SWOT 里的 PEST 方法 —— P 就是政治。

MRD 的组成模块

PRD 的要点

PRD 没有标准格式，但有统一的要求：传达清楚需求。

主要作用：指导项目组成员完成项目开发。

◆ 进企业后的实操三步
  1. 先问要不要写 PRD（很多公司根本不要求）
  2. 如果要写，要求给之前的文档作为参考
  3. 如果要写而且之前没写过，用学校里任意的模板都可以，根据老板或领导的反馈再修改细节

关于非功能性需求

  • 同一个公司中，不同项目的非功能性需求要求几乎都是相同的（抄上一份就行）
  • 不会写就去问开发或测试同事
◆ 课上的定心丸

BRD、MRD、PRD 都是偏制式文档，如果真要求你写，不要紧张，对着模板写就不会出问题。
