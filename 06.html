Figma 实战
产品经理要用的那一半

Figma 是设计师的主力工具，但产品经理只需要用到其中一小部分。这节讲的就是那一部分——搭低保真、连原型、交付给开发。

这一节不是课堂笔记，是替换原课程 Axure 教程后新写的内容。原课程的 06 节是五个 Axure 操作案例（Toast、呼出键盘、省市二级联动、步进器、全局变量），已全部移除。

PART 01

为什么换掉 Axure

不是因为 Axure 做不出东西，而是因为它做的东西留不下来。Axure 原型是一个孤立的 .rp 文件，设计师不用它、开发不看它、改一版要重发一遍。Figma 是一个链接、多人在线、设计和原型同一份文件。

Axure 用户的迁移对照

Axure 里的Figma 里对应差别
页面Frame（画板）Frame 可以嵌套 Frame，页面里能套页面
元件库Component + Library组件改一次，所有引用处同步更新
母版Component同上，Figma 里不分母版和元件
动态面板Component Variant / Overlay多状态切换用变体，弹层用 Overlay
中继器（Repeater）没有对应物需要真数据表格就别在原型工具里做，见 07 节
全局变量Variables能做，但通常不值得 —— 同样见 07 节
生成 HTML 发给别人分享链接不用导出，链接就是最新版
标注（第三方插件）Dev Mode开发自己看，不用你标
◆ 注意这一行

对照表里中继器没有对应物，这不是 Figma 的缺陷。中继器解决的是「在原型工具里模拟一个能增删改查分页的数据表格」—— 这件事本身就该交给真代码，而不是在画图软件里硬凑。

PART 02

四个核心概念

Figma 功能很多，但产品经理搭低保真原型，只需要这四个。

① Frame —— 一切的容器

Frame 是画板，也是容器。它和 Group（编组）看起来像，实际差别很大：

FrameGroup
本质一个盒子，有自己的尺寸只是把几个东西打包
裁剪内容可以（超出部分裁掉）不行
能否 Auto Layout可以不行
子元素改大Frame 尺寸不变Group 跟着一起变大
什么时候用默认都用 Frame临时挪几个图形时才用
⚠ 新人第一个坑

习惯性按 ⌘G 编组。在 Figma 里默认应该用 Frame，不是 Group —— 因为只有 Frame 能上 Auto Layout，而 Auto Layout 是下面这一整节的主角。

② Auto Layout —— Figma 和 Axure 真正的分水岭 ★

这是产品经理最该学会的一个功能，没有之一。Axure 是绝对定位：每个元素钉在坐标上，加一行字要手动挪下面所有东西。Auto Layout 让容器像网页一样自动排列。

三个尺寸模式，必须分清

Auto Layout 容器里每个元素的宽高有三种行为，这是最容易懵的地方：

◆ 一个判断口诀

内容决定大小 → Hug；容器决定大小 → Fill；都不决定 → Fixed。

按钮包着文字走（Hug），输入框撑满一行（Fill），头像永远 40×40（Fixed）。快捷键 Shift + A 给选中元素加 Auto Layout。

③ Component —— 改一处，全局生效

把一个按钮做成组件（主组件 Main），页面里放的都是它的实例 Instance。改主组件，所有实例同步更新。这正是第 05 节说的「PC 端靠组件保证统一」。

④ Styles 与 Variables —— 把「值」变成「名字」

不要在每个元素上手填 #5EEAD4，而是定义一个叫 主色 的样式或变量，元素引用它。改主题时改一处即可。

StylesVariables
管什么颜色、文字、阴影、栅格颜色、数字、字符串、布尔
能力一组固定的样式定义支持多套模式（如明亮/暗色一键切换）
产品经理要用吗低保真定 3-4 个灰阶就够了解概念即可，通常是设计师在维护
◆ 低保真的极简配色

做低保真原型，整套稿子只需要四个颜色：深灰（正文）、中灰（次要信息）、浅灰（分隔线/占位块）、一个强调色（只用在当前主操作上）。这样既满足第 05 节「黑白灰」的要求，又能让评审一眼看到主流程。

PART 03

做交互原型

Figma 的原型交互，本质就是第 05 节那个三步法：什么触发 → 什么效果 → 怎么实现。在 Figma 里，就是从一个元素拉一条线到另一个 Frame，然后配触发方式和动作。

值得学的两个
Overlay（弹层） —— 弹窗、Toast、底部弹起菜单全靠它，不用为每个弹窗单独做一页。

Smart Animate —— 两个 Frame 里同名的图层会自动补间动画。做展开收起、卡片放大很省事。
别急着碰的两个
Interactive Component —— 组件内部做交互，很酷但容易把文件搞乱。

Variables + 条件逻辑 —— 能在原型里做计数、判断。这就是新时代的中继器陷阱 —— 见下一节。
⚠ 别掉进同一个坑

Figma 现在也能用变量做出「点一下数量 +1」「登录成功才跳转」这类逻辑。能做，不代表值得做。

当你发现自己在 Figma 里搭一个真的能算数、能存状态的东西时，停下来 —— 这跟当年在 Axure 里死磕中继器是同一个错误。那一步该交给 07 节的 AI 生成 HTML 原型，二十分钟就能得到一个真能跑的东西。

PART 04

交付给开发

Figma 相比 Axure 最实际的改善：你不用再标注了。开发自己点开元素就能看到尺寸、颜色、字号、间距，还能直接取到对应的代码片段和切图。

开发要什么在 Figma 里怎么拿产品经理要做什么
尺寸和间距选中元素直接看把 Auto Layout 用对，间距才是有意义的数
颜色和字号同上，能直接复制色值用 Styles，别每个地方手填颜色
切图资源自行导出所需倍率确认图标是矢量、命名清楚
交互逻辑Figma 里没有这才是你的活 —— 写在 PRD 和全局说明里
边界情况Figma 里没有第 05 节那份交互自查清单
◆ 这张表最该记的是后两行

Dev Mode 把「标注」这件体力活自动化了，所以产品经理省下来的时间应该花在它替代不了的地方：交互逻辑、边界情况、异常流程。

一份只有漂亮界面、没有空态和报错说明的稿子，在 Figma 时代反而更容易被看穿 —— 因为界面本身已经不值钱了。

⚠ 一个要提前确认的事

Dev Mode 属于 Figma 的付费功能，团队里开发有没有席位，直接影响你的交付方式。具体价格和席位政策以 Figma 官网为准（这类信息变动频繁）。进公司第一周就问清楚，别到交付那天才发现开发打不开。

PART 05

产品经理该会到什么程度

产品经理学 Figma 的目标不是「画得好看」，是能把脑子里的流程快速摆出来给别人看。摆得够清楚就停手。

PART 06

常见误区

🎨
误区一：把低保真做成高保真
Figma 里配色太方便，一不留神就做成了成品图。结果评审全在讨论视觉，没人看流程。主动克制，回到第 05 节那句「最好的原型是黑白灰的」。
🧱
误区二：一上来就建设计系统
还没有三个页面就先花两天搭组件库。第三次重复时再抽组件，前两次直接复制粘贴更快。
🔗
误区三：连线连出一团麻
每个按钮都连，最后自己都看不懂。只连主流程 —— 原型是用来讲清一条路径的，不是穷举所有路径。
⚙️
误区四：在原型里做真逻辑
用变量做出能算数、能存状态的原型。这是中继器的翻版。需要真逻辑就去写代码，下一节讲怎么让 AI 二十分钟给你一个。
